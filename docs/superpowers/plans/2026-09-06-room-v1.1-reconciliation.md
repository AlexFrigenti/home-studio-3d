# Room v1.1 Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an additive `room-v1.1` contract that preserves observed measurements while allowing explicitly authorized reconciled geometry for deterministic closure.

**Architecture:** Keep `room-v1.schema.json` and existing synthetic fixture unchanged. Add a `room-v1.1` schema with optional segment-level `reconciled_geometry` and boundary-level `reconciliation`; teach the validator and pure generation plan to resolve an effective geometry length without overwriting observed data.

**Tech Stack:** JSON Schema draft 2020-12, Python standard library, `unittest`, deterministic pure-Python generation-plan tests. Blender/MCP and `.blend` generation are out of scope for this implementation run.

**Spec:** Approved design in the conversation and `specs/002-room-measurement-and-reconstruction/spec.md`.

## Global Constraints

- `room-v1.schema.json` and `room-v1-synthetic.json` remain semantically and physically unchanged.
- `schema_version: "1.0"` keeps the existing validator and generator behavior.
- `schema_version: "1.1"` is required for reconciled geometry.
- Observed `length.value` is never overwritten by reconciled geometry.
- `effective_length` is reconciled length when present, otherwise observed length.
- Unknown lengths are never materialized silently.
- Reconciliations require derived status, formula, dependencies, reason, source, and an authorized adjustment cap.
- No real room JSON, `plano_blender.py`, Blender, MCP, `.blend`, commit, push, PR, merge, or rebase.
